# Elysium 3D Explorer — Kiosk + Web интерактив систем (төлөвлөгөө)

> **Төлөв:** санал, батлагдаагүй · **Огноо:** 2026-10-24 · **Салбар:** `claude/3d-interactive-system-plan-fh6ca8`
>
> **Хамрах хүрээ:** борлуулалтын оффисын мэдрэгч дэлгэц (kiosk) болон вэб дээр **нэг кодоор**
> ажиллах систем. Хэрэглэгч **төслийн байршлаас эхлээд → хотхон → блок → давхар (B2, B1, 1–23)
> → айл → өрөө доторх аялал** хүртэл тасралтгүй 3D орчинд шилжинэ.

---

## 0. Товч дүгнэлт

- **Нэг codebase, хоёр горим.** Одоогийн Next.js 16 repo дотор `/explore` (вэб) ба `/kiosk`
  (мэдрэгч дэлгэц) гэсэн хоёр орох цэгтэй, ижил 3D scene ашиглана. Kiosk нь Chromium kiosk
  горимд, offline-first ажиллана.
- **Hybrid 3D.** Байршил → хотхон → блок → давхар → зоорь → айл (dollhouse) хүртэл
  **real-time 3D** (three.js + React Three Fiber). Өрөө доторх аялал нь рендерийн студийн
  **photoreal 360° панорам** — Matterport маягийн «dollhouse ↔ panorama» шилжилт.
- **Өгөгдөлд суурилсан 3D.** 506 айл, 513 зогсоолын статус Supabase-д хадгалагдаж (эсвэл
  Vertmonhub-аас sync), 3D загвар дээр өнгөөр шууд харагдана. Статус өөрчлөгдвөл kiosk болон
  вэб дээр бодит хугацаанд шинэчлэгдэнэ.
- **Lead → CRM.** Сонгосон айл/зогсоолын ID-тэй хүсэлт одоогийн `/api/contact` → Vertmonhub
  урсгалаар явна. Kiosk-оос QR уншуулж утсан дээрээ үргэлжлүүлнэ — `utm_source=kiosk`-ийг
  одоогийн attribution систем автоматаар барина.
- **Хугацаа (тооцоо):** вэб MVP ≈ 7 долоо хоног, бүрэн систем + kiosk суурилуулалт ≈ 14
  долоо хоног (+2 долоо хоногийн нөөц) — asset-ууд цагтаа ирвэл.
- **Хамгийн том эрсдэл:** 3D эх файл, B1/B2-ын зураг, 506 айлын бүрэн жагсаалт. Эдгээрийг
  1-р долоо хоногт авах шаардлагатай (§6).

## 1. Зорилго ба амжилтын хэмжүүр

1. Худалдан авагч байраа **харж, мэдэрч, сонгох** — давхар, цонхны чиг, нар, харагдац,
   зогсоол хүртэл нэг дороос.
2. Борлуулалтын менежерийн танилцуулгын хэрэгсэл (kiosk, таблет, вэб).
3. Сонирхлыг **айлын түвшинд** хэмжих — аль тип, аль давхар, аль блок хамгийн их үзэгдэж байна.

**Санал болгож буй зорилт (KPI):**

| Хэмжүүр | Зорилт |
|---|---|
| Kiosk-ийн нэг сессийн дундаж хугацаа | ≥ 3 мин |
| Айлын түвшинд (L4) хүрсэн сесс | ≥ 50% |
| Kiosk → QR / хүсэлт хөрвөлт | ≥ 10% |
| Вэб: постер (LCP) / эхний 3D кадр — 4G, дунд зэргийн утас | ≤ 2.5 сек / ≤ 5 сек |
| FPS | kiosk 60 · desktop ≥ 50 · утас ≥ 30 |
| 3D-ээс ирсэн хүсэлтэд айлын ID | 100% |

### 2.2 Дутуу байгаа зүйлс

- **B1, B2 (зоорь)**-ийн зураг — 513 зогсоолын дугаарлалт, агуулах, лифтний цөм, рамп.
- 1-р давхар (лобби / үйлчилгээ) ба дээврийн зураг.
- Блок бүрийн давхрын тоо, айлын дугаарлалт → **506 айлын бүрэн жагсаалт** (статус, үнэ).
- 3D эх файлууд (гадна тал, интерьер, хотын орчин) — repo-д одоо зөвхөн рендер зураг бий.
- POI-ийн координат, зай, ангилал.

### 2.3 Анхаарах хоёр зөрүү

1. **Айлын тоо.** Брошурын хуваалтаар нэг давхарт 5 айл (2F: E-1…E-5, 3–23F: E-3…E-7) →
   нэг блокт 5 × 22 = 110, дөрвөн блокт **440**. Сайтад **506** гэж бичсэн (өмнө нь 440 байсныг
   506 болгосон — `docs/REDESIGN-PLAN.md`). 3D систем айл бүрийг газар дээр нь байрлуулах тул
   **блок, давхар бүрийн яг жагсаалт** хэрэгтэй — зарим блок өндөр, эсвэл өөр хуваалттай байж
   магадгүй.
2. **«B1/B2» нэрийн давхцал.** Одоогийн «Өрөөний сонголт» хэсэгт `B1/B2` нь **блокийн**
   шүүлтүүр (`apartments.units[].block`). Энэ төлөвлөгөөнд `B1/B2` = **газар доорх (зоорийн)
   давхар**. Төөрөгдөл гаргахгүйн тулд блокуудыг «1–4-р блок» гэж нэрлэж, `B1/B2`-ыг зөвхөн
   зоорьд үлдээхийг санал болгож байна (§9).

## 3. Хэрэглэгчийн аялал — 6 түвшин

```
 L0 Байршил ──► L1 Хотхон ──► L2 Блок ──► L3 Давхар ──► L4 Айл ──► L5 Өрөөний аялал
 (хот, POI)     (masterplan,   (цамхаг,    (айлын        (3D        (photoreal 360°,
                 нар, сүүдэр)   шүүлтүүр)   статус)       dollhouse)  өрөө хооронд алхах)
                     │
                     └──► B1 / B2 зоорь (зогсоол, агуулах, лифт, рамп)
```

Бүх түвшин **нэг 3D орчин** дотор: хуудас дахин ачаалагдахгүй, **камер нисэж** шилжинэ.
Түвшин бүрд URL өөрчлөгдөж, шууд холбоос (deep link) болно.

### L0 — Байршил (хот)

- **Харагдах:** ~2 км радиусын хотын орчин — `location-aerial.jpg`-тэй ижил «цагаан шавар»
  хэв маягаар: бүх барилга цагаан, зөвхөн Elysium-ийн 4 цамхаг брэндийн өнгөтэй. Газрын
  гадарга, Туул гол, Үндэсний цэцэрлэгт хүрээлэн, цаана нь Богд уулын силуэт.
- **POI:** ангиллаар шүүнэ (сургууль, цэцэрлэг, эмнэлэг, худалдааны төв, парк, зам/гүүр).
  Цэг дээр дарахад одоогийн `MonoMap`-ийн картын загвараар зураг, нэр, зай, **явган ба
  машинаар хэдэн минут** гарна.
- **Үйлдэл:** эргүүлэх, томруулах (хязгаартай); «Хотхон руу орох» → камер цамхгууд руу нисэж L1.
- **Чиглэл:** вэб дээр Google Maps-ийн холбоос, kiosk дээр QR.

### L1 — Хотхон (masterplan)

- **Харагдах:** 4 цамхаг, подиум, хашааны тохижилт (тоглоомын талбай, явган зам, ногоон
  байгууламж), орц, зоорийн рамп, хөрш барилгууд.
- **Hotspot:** тохижилт, лобби, үйлчилгээний талбай, зоорийн орц → одоогийн рендерүүд
  (`amenity-*`, `aerial-courtyard-*`).
- **Нар ба сүүдэр:** огноо, цагийн гулсуур — Улаанбаатарын координатаар нарны бодит байрлал
  (`suncalc`), сүүдэр хөдөлнө. «Өвөл (12/21)», «Зун (6/21)» товч. Цастай өвлийн горим — сонголтоор.
- **Үйлдэл:** цамхаг дээр дарах → L2; «Зоорь» товч → B1/B2.

### L2 — Блок (цамхаг)

- **Харагдах:** сонгосон цамхаг, давхар бүр «зүсмэл» болж сонгогдоно. Давхрын хажууд тухайн
  давхарт **хэдэн айл сул** байгааг тоогоор.
- **Шүүлтүүр:** өрөөний тоо (2/3/4), талбай (м²), цонхны чиг (зүүн/баруун/хойд/урд),
  давхрын муж, үнэ (зөвшөөрвөл), статус. Тохирох айлууд фасад дээр **гэрэлтэж**, бусад нь
  бүдгэрнэ. Хажууд нь жагсаалт — жагсаалтаас сонгоход камер тухайн айл руу нисэнэ.
- **Үйлдэл:** давхар сонгох → L3. Давхрын босоо гулсуур kiosk дээр гарт ойр байрлана.

### L3 — Давхар

- **Харагдах:** сонгосон давхрын plate ялгарч, дээд давхрууд тунгалаг болох эсвэл дээш
  «задарна». Айлууд **статусын өнгөөр**: Боломжтой · Захиалсан · Зарагдсан · Худалдаанд
  гараагүй. Айлын шошго (`E-3`, дугаар `2-0703`), луужин, лифт/шат, коридор, нарны чиглэл.
- 2-р давхар өөр хуваалттай (E-1, E-2) — plate-ийн төрөл (2F / TYP) өгөгдлөөс шийдэгдэнэ.
- **Үйлдэл:** айл дээр нэг дарах → карт (тип, талбай, өрөө, чиг, давхар, статус, [үнэ]);
  «Дэлгэрэнгүй» → L4.

### B1 / B2 — Зоорийн давхар

- **Харагдах:** подиум, тохижилт «рентген» маягаар тунгалаг болж, доорх B1, B2 ил гарна
  (хоёуланг нь зэрэг эсвэл задалж). 513 зогсоолын байр, багана, жолооны зам, рамп, блок
  бүрийн **лифтний цөм**, агуулах (байгаа бол), EV цэнэглэгч.
- **Үйлдэл:** байр дээр дарах → карт (дугаар, түвшин, хэмжээ, төрөл: энгийн / том / EV /
  хөгжлийн бэрхшээлтэй, статус, [үнэ], **хамгийн ойр лифт ба зай метрээр**). «Миний блок»
  шүүлтүүр → тухайн блокийн лифтэнд ойр байрууд тодорно. Рампаас байр хүртэл, байрнаас лифт
  хүртэлх замыг шугамаар харуулна.
- **Хүсэлт:** айлтай хамт зогсоол, агуулах сонирхох — нэг хүсэлтэд.

### L4 — Айл (3D dollhouse)

- **Харагдах:** таазгүй, тавилгатай 3D айл. Өрөө бүрд нэр, талбай (`UNIT_PLANS`-аас, ж:
  «Зочны өрөө 19.91 м²»); нийт талбай, тип, давхар, чиг, статус.
- **Хэрэгсэл:** 2D план ↔ 3D; тавилгатай / хоосон; аксонометр рендерүүд; **цонхоор харах** —
  тухайн давхрын бодит өндрөөс хотын 3D загвар руу харсан симуляц; **нарны цаг** — сонгосон
  өдөр өрөөнд шууд нар тусах хугацаа (Phase 4).
- **CTA:** «Сонирхох» (айлын ID-тэй хүсэлт) · «Утсандаа үргэлжлүүлэх» (QR) · «Харьцуулах»
  (3 хүртэл айл) · «Хуваалцах» · «Аялал эхлүүлэх» → L5.

### L5 — Өрөөний аялал (360°)

- **Харагдах:** өрөө бүрийн photoreal 360° панорам. Шалан дээрх цагираг дээр дарж дараагийн
  цэг рүү «алхана» (зөөлөн шилжилт). Буланд мини план — одоо байгаа цэг, харж буй чиглэлийн конус.
- **Мэдээллийн hotspot:** материал, тоног төхөөрөмж — «Барилгын бүтэц» хэсгийн агуулга
  (гурван давхар шилтэй вакум цонх, дулаалгатай метал фасад г.м.).
- **Утсан дээр:** gyroscope-оор харах. **Сонголтоор:** WebXR VR горим, өдөр/шөнийн хувилбар,
  интерьерийн өнгө сонгох.
- Нэг типийн бүх айл нэг аяллыг хуваалцана: 7 тип × 6–9 цэг ≈ **50–60 панорам**. Толин
  тусгал (mirror) хуваалттай айл байвал тусад нь рендерлэнэ.

### 3.1 Нийтлэг UX дүрэм

- **Breadcrumb** үргэлж харагдана: `Байршил › Хотхон › 2-р блок › 7-р давхар › 2-0703 ›
  Зочны өрөө` — аль ч алхам руу буцна; «Эхлэл» товч.
- **Нэг дарах = сонгох, хоёр дахь үйлдэл = гүнзгийрэх.** Kiosk дээр санамсаргүй шилжилтээс
  сэргийлнэ. Вэб дээр hover хийхэд outline ба товч tooltip.
- **Статус зөвхөн өнгөөр биш** — өнгө + шошго/хээ, тайлбар (legend) үргэлж харагдана. Санал:
  боломжтой = брэндийн lime, захиалсан = шаргал + судал, зарагдсан = саарал, худалдаанд
  гараагүй = цагаан хүрээ.
- **Камерын хязгаар:** түвшин бүр «гэр» өнцөг, min/max зайтай; зоорийн горимоос бусад үед газар
  доогуур орохгүй; «Харагдацыг сэргээх» товч.
- **Дэлгэцийн байрлал:** босоо kiosk-д 3D дээд 60%, удирдлага доод 40%; утсанд доороос гарах
  (bottom sheet) самбар; desktop-д баруун талын самбар.
- **Хөдөлгөөн багасгах** (`prefers-reduced-motion`): нисэх анимэйшний оронд зөөлөн fade.
- **3D-гүй горим:** WebGL дэмжихгүй эсвэл сул төхөөрөмж → 2D горим (давхрын зураг, аксонометр,
  интерьерийн зураг). Мэдээлэл бүгд хүртээмжтэй хэвээр.

## 4. Kiosk ба Web — нэг код, хоёр горим

| | Kiosk (борлуулалтын оффис) | Web (`elysium.mn/explore`) |
|---|---|---|
| Дэлгэц, оролт | 55–75" 4K мэдрэгч дэлгэц, multi-touch | Desktop / утас, хулгана / мэдрэгч |
| Чанар | **Ultra**: 4K текстур, зөөлөн сүүдэр, SSAO, bloom | `detect-gpu`-ээр автомат: high / medium / low |
| Сүлжээ | **Offline-first**: бүх asset урьдчилан cache-д, статус онлайн үед sync | CDN-ээс шат шатаар ачаална |
| Сесс | 90 сек хөдөлгөөнгүй → **attract mode**, бүх төлөв, оруулсан мэдээлэл цэвэрлэгдэнэ | Энгийн, deep link, хуваалцах |
| Хүсэлт | **QR → утсан дээрээ үргэлжлүүлэх** (гараас бичих шаардлагагүй) эсвэл дэлгэцийн гар | Одоогийн маягт (`/api/contact`) |
| Нэмэлт | **Менежерийн горим** (PIN): үнэ, hold, харьцуулалт; алсын хяналт | SEO, айл/тип бүрийн OG зураг, Meta Pixel |
| Аналитик | `kiosk_id`-тэй сесс | UTM attribution-тэй сесс |

### 4.1 Kiosk-ийн онцлог ажлууд

- **Attract mode:** хот → хотхон → цамхаг → айл гэсэн кино маягийн камерын аялал давтагдаж,
  «Дэлгэцэнд хүрч эхлэнэ үү» гэсэн урилга гарна.
- **QR handoff:** QR = `https://elysium.mn/explore/unit/2-0703?utm_source=kiosk&utm_medium=qr&utm_campaign=<kiosk-id>`
  → утсан дээр яг тэр айл нээгдэж, хүсэлтийн маягт бэлэн байна. Одоогийн
  `LeadAttributionCapture` UTM-ийг барьж хүсэлтэд хавсаргана (Vertmonhub талд `kiosk` сувгийн
  дүрэм нэмнэ). Серверт нэмэлт төлөв хадгалах шаардлагагүй.
- **Offline:** Service Worker хувилбартай manifest-ээр бүх 3D asset-ыг урьдчилан татна (kiosk-д
  ~0.5–1 GB зөвшөөрөгдөнө). Шинэчлэлтийг **зөвхөн idle reset-ийн үед** хэрэглэнэ — сессийн
  дундуур биш. Интернэт тасарвал хүсэлтүүд IndexedDB-д хадгалагдаж, холболт сэргэхэд
  илгээгдэнэ — нэг ч lead алдагдахгүй. Статусын хажууд «сүүлд шинэчилсэн: 10:42».
- **Менежерийн горим:** PIN → богино хугацааны token; үнэ, hold, айлын танилцуулга PDF
  илгээх. 5 мин идэвхгүй бол автоматаар гарна.
- **Алсын удирдлага:** kiosk бүр минут тутам heartbeat (хувилбар, FPS, сүүлийн алдаа) илгээж,
  админы «Kiosks» самбарт харагдана; «дахин ачаалах» командыг Realtime broadcast-аар өгнө.
- **Хуваарь:** ажлын цагаар (Даваа–Ням 09:00–18:00) асаж, шөнө дэлгэц унтарна.

## 5. Техникийн шийдэл

### 5.1 Хандлагын сонголт

| Хандлага | Давуу тал | Сул тал | Шийдвэр |
|---|---|---|---|
| **A. Web real-time 3D** (three.js / R3F) | Kiosk + вэб нэг код; deep link; одоогийн Next.js, Supabase, админ, CRM-тэй шууд холбогдоно; ажиллуулах зардал бага | Unreal-ийн түвшний photoreal биш; asset-ыг сайн оновчлох шаардлагатай | ✅ **Үндсэн** (L0–L4, B1/B2) |
| **B. Unreal Engine 5 + Pixel Streaming** | Хамгийн бодит дүрслэл | Вэбд зочин бүрд үүлэн GPU сервер (зэрэг хэрэглэгч бүрд цагийн төлбөр), саатал, дараалал; тусдаа codebase, тусдаа баг | ❌ Одоохондоо үгүй — ирээдүйд зөвхөн kiosk-ийн «кино» горимд авч үзэж болно |
| **C. Урьдчилан рендерлэсэн** (кадрын дараалал, 360° панорам) | Ямар ч төхөөрөмж дээр photoreal, хөнгөн | Чөлөөт 3D биш; өөрчлөлт бүрд дахин рендер | ✅ **L5 өрөөний аялал, постерт** |

**Дүгнэлт — A + C hybrid.** Интерактив, өгөгдөлтэй хэсэг (айл сонгох, шүүх, статус)
real-time 3D-д; бодит мэдрэмж хамгийн чухал хэсэг (өрөө дотор) photoreal 360°-д. Энэ нь
Matterport-ийн «dollhouse ↔ panorama» загвартай ижил тул хэрэглэгчдэд танил.

Бэлэн SaaS платформ (real-estate 3D configurator) ашиглахаас өөрсдөө хийх нь давуу:
монгол хэл, брэнд, одоогийн админ/CRM-тэй гүн холболт, өгөгдлийн эзэмшил, сарын хураамжгүй,
Монконы бусад төсөлд дахин ашиглах боломж.

### 5.4 Route ба deep link

| URL | Түвшин |
|---|---|
| `/explore` | L0 Байршил |
| `/explore/site` | L1 Хотхон |
| `/explore/basement/B1`, `/explore/basement/B2` | Зоорь (бүх блокийн доор нэгдсэн гэж үзэв — §9) |
| `/explore/block/2` | L2 — 2-р блок |
| `/explore/block/2/floor/7` | L3 — 7-р давхар |
| `/explore/unit/2-0703` | L4 — айл |
| `/explore/unit/2-0703/tour/living` | L5 — зочны өрөөний панорам |
| `/explore/parking/B1-115` | Зогсоолын байр |
| `/kiosk` | Kiosk бүрхүүл (ижил scene, kiosk UI) |

- `/explore/[[...path]]` catch-all route — нэг `<Canvas>` бүх түвшинд амьд үлдэнэ. Route
  солигдоход WebGL context дахин үүсэхгүй, камер нисэж шилжинэ.

  тулгаж баталгаажуулна.
- Түвшин бүрд server талын `generateMetadata` (гарчиг, тайлбар, OG зураг) — холбоос
  хуваалцахад айлын зураг гарна. MVP-ийн үед `noindex`.

-- Байршил, аялал

- **Статусын эх сурвалж:** Vertmonhub-д айлын бүртгэл байгаа бол → webhook
  `/api/explore/sync` (одоогийн `VERTMONHUB_LEADS_SECRET`-ийн загвараар Bearer нууц) →
  `units.status` → Realtime broadcast. Байхгүй бол → админы «Inventory» хэсэг + Excel/CSV
  импорт (§9).
- **Хүсэлт CRM-д:** эхний ээлжинд айлын мэдээллийг `message`-д бичнэ (одоогийн Vertmonhub
  API-тай шууд нийцнэ); дараа нь Vertmonhub-д тусдаа `interest` талбар (айл, зогсоол) нэмнэ.
- **Үнэ:** public API нь `price_visible = true` үед л үнэ буцаана; менежерийн горимд бүгд.
- **Импортын шалгалт:** нийлбэр (506 айл, 513 байр), давхар бүрийн айлын тоо plate-ийн
  төрөлтэй таарах, тип ↔ талбайн нийцэл.
- **Хандалт:** одоогийнхтой адил сервер `service_role`-оор ханддаг. Клиент зөвхөн цэвэрлэсэн
  JSON (`GET /api/explore/inventory`, CDN cache) ба Realtime broadcast-ын жижиг мессеж
  (`{id, status}`) авна — хүснэгтүүд клиентэд ил гарахгүй.
- **Аналитикийн үйл явдал:** `level_enter`, `unit_view`, `filter_apply`, `tour_start`,
  `tour_node`, `qr_shown`, `lead_submit`, `idle_reset`.

### 5.6 3D ↔ өгөгдлийн холбоос

**Нэршлийн дүрэм (3D artist-д өгөх заавар):** glTF node-ийн нэр = өгөгдлийн түлхүүр.

```
BLK_2           2-р блок
FLR_2_07        2-р блокийн 7-р давхрын plate
UNIT_2_07_03    айл (= units.model_node)
PRK_B1_115      зогсоолын байр
CORE_2          2-р блокийн лифт, шатны цөм
RAMP_1          зоорийн рамп
POI_<id>        байршлын цэг
```

**Хэмнэлт:** 3–23-р давхар ижил тул нэг plate-ийг **instancing**-ээр 21 удаа × 4 блок
давтана. Айлуудыг 506 тусдаа модель болгохгүй — CAD (DWG)-аас plate тус бүрийн айлын хил
(полигон)-ийг нэг удаа гаргаж, runtime-д давхрын өндрөөр extrude хийн сонгох, тодруулах
эзлэхүүн үүсгэнэ. 513 зогсоол мөн CAD-ын координатаас instancing-ээр. Ингэснээр загвар
хөнгөн, статус өөрчлөгдөхөд дахин моделлох шаардлагагүй.

### 5.7 Asset pipeline

```
Архитектор / студи (Revit · ArchiCAD · 3ds Max · SketchUp · DWG)
  → Blender: цэвэрлэх, нэршил, LOD, UV, гэрэл / AO bake (lightmap)
  → .glb
  → gltf-transform: dedup · prune · weld · simplify (LOD) · meshopt · KTX2 (ETC1S / UASTC)
  → hash-тай файлын нэр + manifest.json (хувилбар) → CDN
CAD (DWG/DXF) → Python (ezdxf) → айл, зогсоолын полигон JSON
Интерьер scene → 360° equirect 8K → cubemap / multi-res tile (512 → 4K) → CDN
```

- Скриптүүд `scripts/explore/`-д (одоогийн `scripts/axono.py`, `build-*.mjs`-тэй ижил
  загвараар). `verify:explore-assets` — asset төсөв хэтэрвэл алдаа өгнө.
- **3D asset git-д орохгүй** (`public/` аль хэдийн ~230 MB). Эх файл (.blend, DWG) нь Drive
  зэрэг хадгалалтад, оновчилсон .glb / .ktx2 нь CDN-д, repo-д зөвхөн manifest.
- **Хотын орчин (L0):** (1) студийн massing загвар — хамгийн сайн, брэндийн рендертэй ижил;
  (2) байхгүй бол OpenStreetMap (барилгын өндөр, зам, гол) + DEM газрын гадаргаас Blender-ээр
  үүсгэнэ; (3) Google Photorealistic 3D Tiles — Улаанбаатарын хамрах хүрээ баталгаажаагүй,
  онлайн + API түлхүүр шаардана → зөвхөн вэбийн нэмэлт сонголт.
- «Цагаан шавар» хэв маяг текстургүй тул маш хөнгөн — утсан дээр ч хурдан.
- POI-ийн явган, машинаар явах хугацааг нэг удаа тооцоолж (routing API) хадгална.

   статус, [үнэ]; 513 зогсоол — түвшин, дугаар, төрөл, статус, [үнэ]; агуулах (байгаа бол).
4. **B1/B2-ын баталгаажуулалт:** газар доорх зогсоол мөн үү, бүх блокийн доор нэгдсэн үү, аль
   лифт зоорь хүртэл бууна, газрын дээрх зогсоол хэд вэ.

**P1 — 2–3-р долоо хоногт:**

5. **360° панорамын захиалга** (студи) — доорх спекээр. *Рендер удаан тул хамгийн эхэнд захиална.*
6. Интерьерийн тавилга, материалын эх файл (dollhouse-д) — эсвэл өөрсдийн хөнгөн тавилгын сан
   ашиглах зөвшөөрөл.
7. POI жагсаалт: нэр, ангилал, координат, зураг.
8. Фасад, интерьерийн материалын жагсаалт (hotspot-ын тайлбарт).

**P2 — дараа нь:**

9. Барилгын талбайгаас дроноор авсан 360° зураг (~15, 30, 45, 60 м өндөрт) — «цонхоор
   харах»-ыг бодит зургаар баталгаажуулах.
10. Kiosk байрлуулах цэгийн зураг, хэмжээ, цахилгаан, интернэт.

**360° панорамын спек (студид өгөх):**

| Үзүүлэлт | Утга |
|---|---|
| Формат | Equirectangular JPG (эсвэл 6 талт cubemap), sRGB |
| Нягтрал | 8192 × 4096 (хамгийн багадаа 6144 × 3072) |
| Камерын өндөр | 1.6 м, бүх цэгт ижил |
| Гэрэлтүүлэг | Бүх цэг, бүх типэд ижил цаг, тохиргоо — шилжилт тасархай харагдахгүй |
| Цэгүүд | Тип бүрд 6–9: үүд, коридор, зочны өрөө, гал тогоо, унтлагын өрөө бүр, ариун цэврийн өрөө, лодж |

| Байрлал | Цэг бүрийн (x, y) — давхрын зургийн координатаар, панорамын төвийн чиглэл (хойд зүгээс градусаар) → hotspot-уудыг **автоматаар** тооцоолно |

## 7. Үе шат ба хугацаа

### Phase 0 — Судалгаа, asset, прототип (1–2-р долоо хоног)

- Kickoff; §9-ийн асуултуудад шийдвэр; §6-гийн P0 asset авах; 360° захиалах; kiosk тоног
  төхөөрөмж сонгох.
- **Tech spike:** студийн цамхгийн загварыг R3F прототипд ачаалж, зорилтот төхөөрөмжүүд
  (хуучин Android, iPhone, kiosk PC) дээр FPS, санах ой хэмжих; Serwist + Next 16 нийцлийг шалгах.
- **UX:** 6 түвшний wireframe — kiosk (босоо/хэвтээ), утас, desktop.
- ✅ **Шалгуур:** хамрах хүрээ батлагдсан, P0 asset бүрэн, прототипийн гүйцэтгэлийн тайлан.

### Phase 1 — Суурь + Web MVP (3–7-р долоо хоног)

- Supabase migration; админы Inventory (засах, Excel импорт, лог); public inventory API.
- Scene framework: нэг Canvas, түвшний state machine, URL deep link, камерын шилжилт, чанарын
  түвшин, ачааллын progress, 2D горим.
- **L1 Хотхон, L2 Блок, L3 Давхар** (2F, TYP plate) — статусын өнгө, шүүлтүүр, жагсаалт,
  айлын карт.
- L4-ийн эхний хувилбар: 2D план + аксонометр + өрөөний жагсаалт; 1–2 типийн 3D dollhouse (pilot).
- Хүсэлтэд `unitId` нэмэх (Vertmonhub талтай тохирох).
- ✅ **Шалгуур:** `/explore` (noindex) дээр борлуулалтын баг айл хайж, хүсэлт илгээж чадна;
  админаас статус өөрчлөхөд 3D дээр шинэчлэгдэнэ.

### Phase 2 — Байршил, зоорь, аялал (8–12-р долоо хоног)

- **L0 Байршил:** хотын орчин, POI, зай/хугацаа, нисэж орох анимэйшн.
- **B1/B2:** 513 байр, статус, лифт хүртэлх зай, рамп, зам.
- **L4** бүх 7 типийн dollhouse; **L5** бүх типийн 360° аялал, мини план, hotspot.
- ✅ **Шалгуур:** L0 → L5 бүтэн аялал вэб дээр; утсан дээр ≥ 30 FPS.

### Phase 3 — Kiosk (10–12-р долоо хоног, Phase 2-той зэрэгцээ)

- `/kiosk`: attract mode, idle reset, том мэдрэгч UI, QR handoff, менежерийн горим, offline
  precache, lead queue, heartbeat, автомат шинэчлэлт.
- Тоног төхөөрөмж суурилуулах, Chrome kiosk ба үйлдлийн системийн lockdown, watchdog, ultra чанар.
- ✅ **Шалгуур:** оффист суурилагдсан, 72 цагийн тест давсан, интернэтгүй үед ажиллана.

### Phase 4 — Өнгөлгөө, аналитик, нээлт (13–14-р долоо хоног)

- Нарны судалгаа ба нарны цаг, «цонхоор харах», харьцуулалт, айлын танилцуулга PDF (хүсэлттэй),
  OG зураг, аналитикийн самбар (хамгийн их үзэгдсэн айл/тип/давхар, L0 → хүсэлтийн юүлүүр).
- Төхөөрөмжийн матриц дээр QA, хүртээмжийн шалгалт, гүйцэтгэлийн тааруулга.
- Нүүр хуудаснаас холбох: VR хэсгийн «тун удахгүй» → «3D-ээр үзэх»; «Өрөөний сонголт»-ын
  картанд «3D-д харах».
- ✅ **Шалгуур:** KPI хэмжигдэж эхэлсэн, production нээлт.

### Phase 5 — Backlog (сонголтоор)

- Gaussian splat (чөлөөтэй алхах) — үзүүлэн айл баригдсаны дараа бодит скан эсвэл рендерээс.
- WebXR VR горим, интерьерийн материал/өнгө сонгогч, ипотекийн тооцоолуур.
- Байгалийн хэлээр хайх: «10-аас дээш давхарт, нар сайн тусдаг 3 өрөө» → шүүлтүүр (одоогийн
  keyword чатботыг LLM-ээр сайжруулах).
- Монконы бусад төсөлд дахин ашиглах (`projects` хүснэгт).
